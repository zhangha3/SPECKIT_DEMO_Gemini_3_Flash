# Requirements Quality Checklist (Unit Tests for Requirements)

**Feature**: 用户登录、舱位购买及订单查询 (003-user-auth-ordering)
**Status**: Draft
**Date**: 2026-01-13

## 1. 用户认证与权限 (Auth & Permissions)
- [x] **FR-001 (登录页)**: 是否包含用户名、密码输入框及登录按钮？登录失败时是否有反馈？
- [x] **FR-002 (数据初始化)**: 首次运行是否成功加载 5 个默认用户？`users.json` 缺失时是否抛出合理异常？
- [x] **FR-006/009 (会话管理)**: 登录状态是否能通过 `SessionStorage` 持久化？点击“登出”是否立即清除会话并重定向？
- [x] **路由守卫**: 未登录用户直接访问 `/schedules` 或 `/orders` 是否会被强制重定向至登录页？

## 2. 船期展示与库存控制 (Schedules & Inventory)
- [ ] **FR-003/004 (库存展示)**: 船期列表每行是否清晰展示“剩余库存”？数据是否源自 `LocalStorage` 镜像？
- [ ] **FR-005 (状态切换)**: 
    - [ ] 库存 > 0 时，“购买”按钮是否为蓝色/激活状态？
    - [ ] 库存 = 0 时，按钮文本是否显示“暂无库存”且样式变为禁用（Disabled）？
- [ ] **数据源一致性**: 当 `LocalStorage` 中的库存更新后，UI 列表是否同步刷新，无需手动刷新页面？

## 3. 购买流程 (Ordering Flow)
- [ ] **FR-007 (订单生成)**: 点击“购买”后，系统是否即时生成 `ORD-YYYYMMDD-XXXX` 格式的单号？
- [ ] **库存扣减**: 点击购买后，`LocalStorage` 中的对应船期库存是否确切扣减 1？
- [ ] **订单持久化**: 购买成功的订单是否已存入 `orders` 存储数组？记录中是否包含下单时间、下单人及当时的船期快照？
- [ ] **用户反馈**: 下单后是否弹出包含订单号的成功提示？

## 4. 订单查询 (Order History)
- [ ] **FR-008 (列表显示)**: 进入订单页是否默认显示**当前登录用户**的历史订单？
- [ ] **排序规则**: 列表是否严格按照“下单时间倒序”（最新在前）排列？
- [ ] **精确查询**: 输入有效的订单号是否能准确匹配并展示订单快照及其详情？
- [ ] **查询限制 (安全)**: 查询他人订单或无效单号时，是否返回“未找到”提示而非泄露信息？

## 5. 跨功能需求 (Cross-cutting)
- [ ] **性能指标 (SC-001)**: 登录操作响应是否直观感受在 500ms 以内（纯前端逻辑）？
- [ ] **持久化稳定性 (SC-003)**: 关闭浏览器标签页后再重新进入（并再次登录），之前的购买记录是否依然存在？
