## User Scenarios & Testing *(mandatory)*

### User Story 1 - 资金账户管理与充值退款 (Priority: P1)

用户可以通过专门的资金账户页面管理自己的余额。系统支持使用资金密码（默认为123456）进行人民币（CNY）的充值和退款操作。

**Why this priority**: 资金是后续交易的基础，也是该功能的核心部分。

**Independent Test**: 用户登录后进入资金页面，查看初始余额为0，输入资金密码进行充值，余额增加；选择退款并验证密码，余额减少。

**Acceptance Scenarios**:

1. **Given** 用户已登录且进入资金管理页面，**When** 用户输入金额并输入正确的资金密码点击充值，**Then** 账户余额实时增加，并生成一条充值日志。
2. **Given** 用户账户有余额，**When** 用户输入退款金额及错误的资金密码，**Then** 系统提示密码错误，余额不发生变化。
3. **Given** 用户查看日志列表，**When** 用户选择特定日期范围或操作类型（充值/退款），**Then** 列表仅显示符合条件的记录。

---

### User Story 2 - 结合资金扣减的船期舱位购买 (Priority: P1)

用户在购买船期舱位时，系统将根据舱位价格自动从其资金账户扣除相应金额。

**Why this priority**: 实现了资金账户与业务流的闭环，是项目的核心业务逻辑变更。

**Independent Test**: 用户选择一个船期（价格已根据运输天数*5计算），点击购买。购买成功后，检查库存减少且资金账户余额扣除对应价格。

**Acceptance Scenarios**:

1. **Given** 用户资金账户余额充足，**When** 用户点击购买某船期舱位，**Then** 购买成功，余额减少，并记录一条购买支出日志。
2. **Given** 用户资金账户余额不足，**When** 用户尝试购买船期舱位，**Then** 系统提示余额不足，购买失败，库存不减少。

---

### User Story 3 - 经营数据统计与分析可视化 (Priority: P2)

管理人员或用户可以查看系统的经营统计数据，包括订单量和金额的三个维度（时间、船期、用户）分析，并通过图表直观展示。

**Why this priority**: 提供决策支持和业务洞察。

**Independent Test**: 访问统计页面，能够看到柱状图或饼图展示的周/月订单趋势，以及热门船期的排行榜。

**Acceptance Scenarios**:

1. **Given** 系统中存在历史订单数据，**When** 访问统计分析页面，**Then** 页面展示按月份和周分布的订单金额折线图。
2. **Given** 有多个用户的订单，**When** 查看用户维度统计，**Then** 能够看到各用户贡献的订单总额排序。

---

### User Story 4 - 热门船期推荐与快速搜索 (Priority: P3)

在船期查询页面侧边栏展示最近一周最热门的3条船期。

**Why this priority**: 提升用户体验和搜索效率。

**Independent Test**: 生成最近一周的模拟订单，访问查询页，侧边栏应显示销量前三的航线（起始港-目的港）。点击其中一项，搜索框自动填充并触发查询。

**Acceptance Scenarios**:

1. **Given** 侧边栏展示了热门船期，**When** 用户点击某条热门航线，**Then** 主页面的起始港和目的港输入框自动更新为该航线的信息，并立即展示搜索结果。

### Edge Cases

- **资金密码连续错误**: 当用户连续多次输入错误的资金密码时，系统应暂时锁定资金操作。
- **并发扣款**: 当同一用户在多个设备上同时发起涉及资金的动作（如多个订单支付）时，系统应确保余额不会由于并发导致负数。
- **空数据状态**: 当统计页面没有订单数据时，应友好地展示空状态占位符及引导。
- **航线去重**: 热门船期在统计时，如果起始港、目的港完全相同但船号不同，应视为同一条航线进行聚合。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供独立的资金账户管理页面，展示当前 CNY 余额。
- **FR-002**: 充值和退款操作必须经过资金密码验证（默认 123456）。
- **FR-003**: 资金账户仅支持人民币（CNY）币种，暂不处理汇率转换。
- **FR-004**: 每次资金变动（充值、退款、购买支出）必须记录日志，包含时间、类型、金额、余额变动。
- **FR-005**: 船期数据（schedules.json）必须增加 price 字段，默认值为 transit_days * 5。
- **FR-006**: 购买舱位时必须检查余额，成功购买后同步扣除账户金额。
- **FR-007**: 统计页面必须展示按时间（月/周）、船期（港口对）、用户三个维度的订单数和总金额。
- **FR-008**: 统计页面必须包含图表可视化展现。
- **FR-009**: 船期查询页面侧边栏必须展示最近一周成交量前 3 的去重航线。
- **FR-010**: 统计分析页面对所有登录用户开放，用户仅能查看并统计属于自己的订单数据。
- **FR-011**: 充值金额必须为大于 0 的整数，无上限限制；退款金额上限为账户当前可用余额。
- **FR-012**: 热门船期的统计口径为滑动 7 天（从当前时刻倒推 168 小时内生成的订单）。
- **FR-013**: 船期价格在系统初始化加载数据时计算一次（transit_days * 5），后续运行期间不再动态更新。
- **FR-014**: 点击热门船期推荐时，系统应清除现有的所有搜索条件，仅填充对应的起始港和目的港。

### Key Entities *(include if feature involves data)*

- **FundAccount**: 用户的资金账户，包含余额 (balance)、资金密码 (fundPassword)。
- **TransactionLog**: 资金流水，记录用户 ID、变动金额、变动类型、时间戳、剩余余额。
- **OrderStatistics**: 统计聚合实体，包含维度（时间/港口/用户）和指标（订单数/总金额）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户完成一笔充值并验证密码的操作应在 10 秒内完成。
- **SC-002**: 购买舱位时的库存检查与资金扣减必须保持原子性（逻辑层确保同步成功或失败）。
- **SC-003**: 统计页面加载图表的时间不应超过 2 秒（针对 1000 条以内的订单数据）。
- **SC-004**: 热门船期推荐的准确率应为 100%（即确实为最近一周销量最高的 3 个航线）。
- **SC-005**: 95% 的用户在点击热门船期后，能正确看到过滤后的搜索结果。

## Assumptions

- 初始用户的资金金额通过更新 users.json 默认为 0。
- 资金密码目前硬编码为 123456，不提供修改界面。
- 统计数据来源于本地 localStorage 或模拟的后端服务接口。
